# Vulkan 1.3+ Rendering Backend & Render Hardware Interface (RHI)

## 1. Overview & Backward-Compatibility Guarantee

Castle Game Engine (CGE) provides an explicit, modern **Vulkan 1.3+ (up to Vulkan 1.4)** rendering backend alongside its established **OpenGL 3.3–4.6** and **OpenGL ES 3.0–3.2** backends. Both backends are unified beneath an internal **Render Hardware Interface (`CastleInternalRHI`)** while preserving **100% source and runtime backward compatibility** with existing CGE games, X3D/glTF 2.0 assets, UI designs (`.castle-user-interface`), `TCastleWindow`, and embedded `TCastleControl` (Lazarus LCL, CGE Editor, Delphi VCL, Delphi FMX).

### Default Behavior (`backendAuto` -> OpenGL by Default)
- **Zero-Regression Opt-In**: By default (`ApplicationProperties.RenderBackend = backendAuto` and no CLI/environment/manifest override), CGE continues to select its battle-tested **OpenGL / OpenGL ES** renderer with zero behavioral changes or Vulkan loader overhead.
- **Automatic Fallback**: When Vulkan is requested (`render_backend="vulkan"`, `--render-backend=vulkan`, `CASTLE_RENDER_BACKEND=vulkan`, or `ApplicationProperties.RenderBackend := backendVulkan`) on a machine without a compatible Vulkan ICD/GPU, CGE logs a clear diagnostic warning and cleanly falls back to OpenGL / OpenGL ES without crashing.

|              Castle Game Engine Public High-Level APIs                |

+-----------------------------------------------------------------------+
                                   |

+-----------------------------------------------------------------------+

## 2. Quick Start: Enabling Vulkan

You can activate the Vulkan renderer in four ways without modifying your scene graph or game logic:

### 2.1 `CastleEngineManifest.xml` (Project Default + Pre-Warming)
```xml
<?xml version="1.0" encoding="utf-8"?>
<project name="my_game"
  standalone_source="my_game_standalone.dpr"
  render_backend="vulkan"
  bundle_vulkan_caches="true">
</project>
```
- `render_backend="vulkan"` (`auto` | `opengl` | `opengles` | `vulkan`) sets the generated startup backend in `castleautogenerated.pas`.
- `bundle_vulkan_caches="true"` instructs `castle-engine package` (and Android/iOS `CopyData`) to pre-compile and stage `.spv` shader modules into `castle-data:/shader_cache/` (indexed in `CastleDataInformation.xml`) alongside an optional seed `castle-data:/vulkan_pipeline_cache.bin`.

### 2.2 Command-Line Flags (Any Unmodified CGE Binary)
Every `TCastleWindow`-based CGE application accepts standard engine CLI flags:
```bash
# Launch any CGE game or example on Vulkan:
./my_game --render-backend=vulkan

# Automated CI / smoke verification: render 3 frames, save a PNG screenshot, and exit:
CASTLE_VULKAN_VALIDATION=1 ./my_game \
  --render-backend=vulkan \
  --auto-exit-frames=3 \
  --capture-screenshot=/tmp/frame.png
```

### 2.3 Pascal API (Startup Selection & Live Runtime Hot-Switching)
```pascal
uses CastleApplicationProperties, CastleWindow;

// 1. Before opening the window (e.g. initialization or program body):
ApplicationProperties.RenderBackend := backendVulkan;

// 2. Or live at runtime while TCastleWindow / TCastleControl is already open!
// Seamlessly recreates GPU resources and swapchains without losing scene/UI state:
Application.SwitchRenderBackend(backendVulkan);
// Switch back to OpenGL at any time:
Application.SwitchRenderBackend(backendOpenGL);
```
You can also subscribe to `ApplicationProperties.OnRenderBackendChange` to observe backend transitions.

### 2.4 CGE Visual Editor (`castle-editor`)
- **Live Design Viewport Toggle**: Use **Viewport -> Render Backend (OpenGL / Vulkan 1.3+)** to switch the embedded LCL `TCastleControl` design viewport between OpenGL and Vulkan in-place while editing `.castle-user-interface` or `.castle-transform` assets.
- **Run Parameters**: Use **Run -> Run Parameters -> Render Backend** to launch your project from the editor with `--render-backend=opengl` or `--render-backend=vulkan`.
- **System Information**: Open **Help -> System Information** to inspect active Vulkan instance/device versions, driver properties, enabled extensions, PSO cache hits, and GPU memory budget (`VK_EXT_memory_budget`).

| `CASTLE_CAPTURE_SCREENSHOT` | Output `.png` path | Environment equivalent of `--capture-screenshot=<path>`. |

## 4. Shader Compilation Modes & Custom `Effect` / `ScreenEffect` Authoring

### 4.1 Three-Tier SPIR-V Shader Pipeline (`TCastleShaderCompiler`)
1. **Bundled / Cached `.spv` Fast Path (Zero Runtime Compiler Needed)**:
   - At runtime, CGE checks `castle-data:/shader_cache/<hash>.spv` (packaged via `bundle_vulkan_caches="true"`) and `castle-config:/shader_cache/<hash>.spv` first, reflecting descriptor bindings in pure Object Pascal (`InspectSPIRVBytecode`).
2. **56 Built-In Zero-Dependency SPIR-V Modules (`TryGetBuiltInSPIRV`)**:
   - Core 2D UI (`CastleBatch2D`, `DrawPrimitive2D`), 3D Unlit/Phong/Cook-Torrance GGX PBR (32 punctual lights, `sampler2DShadow` PCF & Chebyshev VSM shadows, 4-bone `TSkinNode` GPU skinning, `TCastleBackground` skybox, cubemap/3D/`TMultiTextureNode`, Split-Sum IBL compute convolution), GPU culling/material binning, 9-pass HDR/Bloom/GTAO/SSR post-processing, hardware `VK_KHR_ray_query` / `VK_KHR_ray_tracing_pipeline` / Software LBVH, and `VK_EXT_mesh_shader` / Software Meshlet shaders are embedded directly in `CastleInternalShaderCompiler` so standard CGE scenes render on Vulkan even on stripped systems without `libshaderc` or `glslangValidator`.
3. **Runtime GLSL -> SPIR-V Compilation (`libshaderc` / `glslangValidator` / `glslc`)**:
   - Arbitrary user X3D `Effect` (`TEffectNode` / `TEffectPartNode` `PLUG_*` hooks across Appearance, Texture, Light, and State scopes), `ComposedShader`, `TCastleTerrain`, and `TCastleScreenEffects` GLSL shaders are automatically upgraded to Vulkan GLSL `#version 450` (`TCastleShaderGeneratorRHI`) and compiled to SPIR-V on the fly, then persisted to `castle-config:/shader_cache/`.

### 4.2 Automatic Legacy GLSL -> Vulkan `#version 450` Upgrade Rules
Existing CGE custom shaders continue to work without manual rewrites thanks to `TCastleShaderGeneratorRHI` and `TUserEffectShaderLayout`:

| Legacy CGE / OpenGL Construct | Automatic Vulkan `#version 450` Translation |
| :--- | :--- |
| Loose value `uniform float/vec*/mat* u_foo;` | Gathered by name into `std140` `CastleUserEffectBlock` at `Set 2, Binding 1` with `#define u_foo CastleUserEffect.u_user_u_foo` aliases shared deterministically across Vertex, Geometry, and Fragment stages. |
| Loose sampler `uniform sampler2D/Cube/3D u_tex;` | Assigned deterministic descriptor bindings `CASTLE_SAMPLER(2, 2..9)` (`Set 2, Bindings 2..9`). |
| Per-light `TEffectNode` (`FdEffects` on X3D lights) | Scoped per active light (`castle_light<Idx>_<Name>`) and guarded by `castle_current_light_index == <Idx>u` inside `PLUG_light_scale` across up to 16 per-draw Set 2 descriptor slots. |
| Built-in CGE uniforms (`castle_ModelViewMatrix`, `castle_ProjectionMatrix`, `castle_NormalMatrix`, `castle_LightSource*`, `castle_Material*`) | Commented out as standalone uniforms (`SanitizeVulkanShaderSource`) and resolved via `Set 0` (`CastleSceneBlock`, `CastleLightsBlock`), `Set 1` (`CastleMaterialBlock`), or Push Constants (`CastleDraw`). |
| `attribute` / `varying` qualifiers | Upgraded to `in` / `out` with deterministic cross-stage locations (`CASTLE_LOCATION(16 + K)`). |
| `texture2D` / `texture2DProj` / `textureCube` / `texture3D` | Mapped to modern overloaded `texture(...)` / `textureProj(...)` via compatibility macros; `gl_FragColor` mapped to `layout(location = 0) out vec4 castle_FragColor`. |
| Multiple `PLUG_*` hooks on the same shape | Comments stripped (`StripGLSLComments`), genuine `{`-body definitions renamed (`PLUG_<name>_2..N`), and chained in declaration order. |

### 6.2 Coordinate System & Negative Viewport (`VK_KHR_maintenance1`)
CGE uses bottom-up 2D/viewport rectangles and right-handed Y-up 3D clip coordinates, whereas Vulkan uses top-down framebuffer coordinates and $[0, 1]$ NDC depth:
1. **Negative Viewport Height**: `TVulkanRHICommandList.SetViewport` sets `VkViewport.y := AttachmentHeight - ViewportRect.Bottom` and `VkViewport.height := -ViewportRect.Height`, preserving counter-clockwise (`ffCounterClockwise`) front-face winding without flipping meshes or vertex shaders.
2. **Bottom-Up Scissor, Clear & Readback**: `SetScissor`, `BeginRendering`, and `ClearAttachments` convert `TopY := AttachmentHeight - (Rect.Bottom + Rect.Height)`, while `GrabTextureImage` flips GPU-rendered attachments (`RenderedLayerMask <> 0`) back into CGE's bottom-up image row order.
3. **$[0, 1]$ Depth Remap**: `TCastleShaderGeneratorRHI.FinalizeVertexShaderSource` appends `gl_Position.z = (gl_Position.z + gl_Position.w) * 0.5;` (and `ProjectorScalingMatrixVulkan` maps shadow receiver UV/depth accordingly).

### 6.3 4-Set Descriptor Layout Convention

| Set | Frequency | Contents |
| :---: | :--- | :--- |
| **Set 0** | Per-Frame / Scene Pass | `CastleSceneBlock` (camera/projection/fog/clip planes), `CastleLightsBlock` (up to 32 punctual lights), `castle_shadow_map_0..3` (`sampler2DShadow` / VSM). |
| **Set 1** | Per-Material / Bindless | `CastleMaterialBlock`, PBR/Phong material textures (`BaseColor`, `Normal`, `MetallicRoughness`, `Emissive`, `Occlusion`, IBL `Irradiance`/`Prefiltered`/`BrdfLUT`), or `castle_BindlessTextures[]` + `CastleBindlessMaterialsBlock`. |
| **Set 2** | Per-Object / Custom Effect | `CastleSkinningBlock` (`256` joint matrices), `CastleUserEffectBlock` (`std140` custom `Effect` uniforms), custom samplers & `castle_multi_texture_1..3` (`Bindings 2..9`). |
| **Push Constants** | Per-Draw (`128 B`) | `ModelViewMatrix`, `NormalMatrix`, per-draw `ObjectParams` / 2D `TCastle2DPushConstants`. |

### 7.3 Troubleshooting Common Issues
1. **Custom `Effect` shader falls back or warns that no runtime GLSL compiler was found**:
   - Install `libshaderc` (`apt install libshaderc1` on Ubuntu/Debian, `brew install shaderc` on macOS, or Vulkan SDK `shaderc_shared.dll` on Windows) or `glslangValidator`, **or** package your project on a developer machine with `bundle_vulkan_caches="true"` so end-user builds load pre-compiled `.spv` binaries from `castle-data:/shader_cache/` with zero runtime compiler dependencies.
2. **Laptop / Multi-GPU system selects integrated GPU instead of discrete GPU (or vice versa)**:
   - CGE automatically scores discrete GPUs (`VK_PHYSICAL_DEVICE_TYPE_DISCRETE_GPU`) highest, followed by integrated, virtual, and CPU (`Lavapipe`) adapters. Override at any time via `CASTLE_VULKAN_VENDOR=nvidia|amd|intel` or `CASTLE_VULKAN_DEVICE=<name substring>`.
3. **macOS Homebrew MoltenVK not found when running outside `.app` bundle**:
   - Ensure `brew install molten-vk vulkan-loader` is installed, or point `CASTLE_VULKAN_LIBRARY="$(brew --prefix molten-vk)/lib/libMoltenVK.dylib"` directly at MoltenVK.
4. **Debugging synchronization or descriptor validation warnings**:
   - Run with `CASTLE_VULKAN_VALIDATION=1 CASTLE_VULKAN_VALIDATION_STRICT=1` to enable `VK_LAYER_KHRONOS_validation` and break immediately with full `VK_EXT_debug_utils` object/pass names (`vkSetDebugUtilsObjectNameEXT` + `TRHIRenderGraph` pass scopes).
